# Domain Finder Agent

Агентный пайплайн, который по **ИНН российской организации** находит её **основной
сайт** в интернете и возвращает домен в формате JSON.

Пайплайн построен на **LangGraph**: LLM-агент в цикле вызывает инструменты
(веб-поиск и загрузка страниц), анализирует результаты и возвращает финальный ответ.

## Как это работает

```
input/example.json                output/result.json
{"inn": "7721581040"}   ──────►   {"domain": "dadata.ru"}
        │
        ▼
┌──────────────────────────────────────────────────────────────┐
│  LangGraph-агент (LLM через Caila, OpenAI-совместимый API)   │
│                                                              │
│   ┌────────┐  tool_calls   ┌────────┐                        │
│   │ агент  │ ───────────►  │ tools  │                        │
│   │  (LLM) │ ◄───────────  │        │                        │
│   └────┬───┘  наблюдения   └───┬────┘                        │
│        │ финальный ответ       │                             │
│        ▼                                                   │
│   ┌──────────┐   домен-каталог? ── замечание ──► снова «агент»
│   │ validate │ ──────────────                                │
│   └────┬─────┘   (не более MAX_VALIDATION_RETRIES раз)      │
│        ▼                                                     │
│   финальный ответ: {"domain": "dadata.ru"} или null          │
└──────────────────────────────────────────────────────────────┘
```

1. `web_search` — поиск в интернете по запросам вида «ИНН … официальный сайт»;
   в сниппетах каталогов (rusprofile, checko, list-org и т.п.) часто указан сайт.
   Можно передать `count` (до 100), чтобы получить больше результатов.
   Провайдер переключается переменной `SEARCH_PROVIDER`: `yandex` (по умолчанию,
   Yandex Search API — лучше знакомый с рунетом) или `brave` (Brave Search API).
2. `fetch_page` — загрузка главной страницы домена-кандидата для проверки,
   что сайт действительно принадлежит организации.
3. `validate` — детерминированная проверка ответа: формат домена, домены-заглушки
   (example.com и т.п.), блоклист каталогов/агрегаторов/соцсетей
   (`core/validators.py::BLOCKED_DOMAINS`) и подтверждённость домена наблюдениями
   инструментов (домен обязан встречаться в результатах поиска или на страницах).
   При нарушении агент получает замечание и дорабатывает ответ; финальные гварды
   в `run()` гарантируют null для заглушек, каталогов и неподтверждённых доменов.
   Дословно повторные вызовы инструментов не выполняются — возвращается кэш.
4. Финальный ответ разбирается `JsonOutputParser` по pydantic-схеме `DomainAnswer`:
   парсер достаёт JSON из markdown-блоков и окружающего текста (включая обрезанные
   ответы), а его формат-инструкции встраиваются в системный промпт. Если модель
   ответила не по формату — домен извлекается резервным LLM-вызовом по всей истории.


## Структура проекта

```
├── pipeline.py            # Единая точка входа: input/ → агент → output/
├── demo.py                # Демонстрация работоспособности на наборе кейсов
├── config.py              # Константы и переменные окружения (.env)
├── core/
│   ├── logger.py          # Настройка логирования приложения
│   └── validators.py      # Валидация ИНН, нормализация и проверка доменов
├── agents/
│   ├── prompts.py         # Все системные и пользовательские промпты LLM
│   ├── llm_factory.py     # Фабрика LLM-клиента (OpenAI-совместимый API)
│   └── domain_finder.py   # LangGraph-агент: граф «модель ↔ инструменты»
├── tools/
│   ├── web_search.py      # Инструмент Web Search (диспетчер провайдеров)
│   ├── search_yandex.py   # Провайдер: Yandex Search API v2 (по умолчанию)
│   ├── search_brave.py    # Провайдер: Brave Search API (альтернатива)
│   └── site_fetch.py      # Загрузка страниц (проверка домена)
├── input/
│   └── example.json       # {"inn": "7721581040"}
├── output/                # result.json появляется после запуска
├── tests/                 # Оффлайн-юнит-тесты (unittest, без ключей)
├── .env.example           # Шаблон конфигурации
└── requirements.txt       # Зависимости (зафиксированы точными версиями)
```

## Установка

Требуется Python 3.10+.

```bash
# 1. Виртуальное окружение (если ещё не создано)
python -m venv .venv
.venv\Scripts\activate            # Windows
# source .venv/bin/activate       # Linux/macOS

# 2. Зависимости
pip install -r requirements.txt

# 3. Конфигурация
copy .env.example .env            # Windows
# cp .env.example .env            # Linux/macOS
```

Затем заполните в `.env`:

| Переменная          | Обязательна | Описание                                        |
|---------------------|-------------|-------------------------------------------------|
| `OPENAI_API_KEY`    | да          | Ключ Caila (https://caila.io), формат «caila-...» |
| `YANDEX_SEARCH_API_KEY` | да*     | API-ключ сервисного аккаунта Yandex Cloud       |
| `YANDEX_SEARCH_FOLDER_ID` | да*   | folderId каталога с активированным Search API   |
| `SEARCH_PROVIDER`   | нет         | Провайдер поиска: `yandex` (по умолчанию) или `brave` |
| `BRAVE_API_KEY`     | да*         | Ключ Brave Search — нужен только при `SEARCH_PROVIDER=brave` |
| `LLM_MODEL`         | нет         | Модель из каталога Caila (по умолчанию `gpt-4.1-mini`) |
| `OPENAI_BASE_URL`   | нет         | По умолчанию `https://caila.io/api/openai/v1` |
| `MAX_AGENT_STEPS`   | нет         | Лимит шагов агента (по умолчанию 24)            |
| `MAX_VALIDATION_RETRIES` | нет    | Доработок ответа после замечания validate (2)   |
| `SEARCH_RESULTS_COUNT` | нет      | Результатов на запрос по умолчанию (7)          |
| `LOG_LEVEL`         | нет         | Уровень логов: DEBUG, INFO, WARNING, ERROR (`INFO`) |

\* Без ключей активного провайдера поиска пайплайн запустится, но `web_search`
будет возвращать ошибку и агент вернёт `null`.

### Подключение Yandex Search API

1. Зарегистрируйтесь в [Yandex Cloud](https://yandex.cloud) и создайте платёжный аккаунт.
2. В консоли выберите каталог и активируйте **Search API** (партнёрская программа
   или платная подписка по запросам).
3. Создайте сервисный аккаунт и выпустите для него **API-ключ**.
4. Заполните в `.env`: `YANDEX_SEARCH_API_KEY`, `YANDEX_SEARCH_FOLDER_ID`.

Особенности API: синхронный эндпоинт `/v2/web/search`, ответ — Base64+XML,
до 250 результатов на выдачу, запрос не длиннее 400 символов и 40 слов.
Подробнее: https://yandex.cloud/ru/docs/search-api/

## Запуск

```bash
python pipeline.py input/example.json
# или проще — возьмётся первый *.json из папки input/:
python pipeline.py
```

Результат сохраняется в `output/result.json`:

```json
{"domain": "dadata.ru"}
```

Если сайт не найден или данных недостаточно:

```json
{"domain": null}
```

Дополнительные опции: `python pipeline.py input/example.json -o output/custom.json`.

## Демонстрация на кейсах (demo.py)

`demo.py` проверяет работоспособность пайплайна на наборе кейсов, которые
заданы Python-словарём `DEMO_CASES` прямо в файле (без папки `input/`):

| № | ИНН | Ожидание | Смысл кейса |
|---|-----|----------|-------------|
| 1 | 7721581040 | `dadata.ru` | Базовый: организация с известным сайтом |
| 2 | 7707083893 | `sberbank.ru` (допустим `sberbank.com`) | Проблемный: TLS-сертификат национального УЦ (SSL-fallback) |
| 3 | 7714270020 | `null` | Негативный: ликвидированное ООО без сайта |
| 4 | 1831203731 | `null` | Действующее ООО «Кольцо» (Ижевск) без сайта |
| 5 | 2725016474 | `null` | Действующий ГСК №57 (Хабаровск): только каталоги/соцсети |

```bash
python demo.py        # все кейсы, сводная таблица + output/demo_results.json
python demo.py 2      # только кейс №2
```

Код возврата: `0` — все кейсы пройдены, `1` — есть расхождение с ожиданием.

Замечание о стабильности: позитивные кейсы устойчивы. Негативные кейсы
вероятностны: когда сайта нет, LLM иногда приписывает организации «домен из
шума» выдачи или путает организацию с одноимённой. Детерминированные гварды
(домены-заглушки, каталоги, неподтверждённые домены, дедупликация вызовов,
мягкая проверка ИНН на странице) устраняют большинство таких ошибок.
Проверенная конфигурация: `LLM_MODEL=gpt-4.1-mini` — полный набор кейсов
проходит стабильно (4–16 секунд на кейс).

## Обработка ошибок и логирование

- Валидация входа: формат и **контрольная сумма** ИНН (10/12 цифр), корректность
  JSON, наличие поля `inn`.
- Проверка конфигурации перед запуском: понятная ошибка при отсутствии ключей.
- Все сетевые вызовы имеют таймауты; ошибки инструментов не роняют пайплайн —
  агент получает текстовое сообщение об ошибке и продолжает работу.
- Лимит шагов агента защищает от бесконечных циклов инструментальных вызовов.
- Узел validate проверяет ответ детерминированно (формат + блоклист каталогов)
  и может отправить агента на доработку; LLM-as-a-judge не используется.
- Резервное извлечение ответа: если финальное сообщение модели не удалось
  распарсить, домен извлекается отдельным LLM-вызовом по всей истории.
- Логи пишутся в консоль (`LOG_LEVEL` в `.env`, по умолчанию `INFO`).
- Дословно повторные вызовы инструментов не выполняются — агенту возвращается
  кэшированный результат с пометкой.
- Коды возврата: `0` — успех (включая честный `domain: null`),
  `1` — ошибка входных данных, конфигурации или инфраструктуры.

## Известные ограничения и компромиссы

- **Определение основного сайта**: для российской организации это домен в зоне
  `.ru`; каталоги, агрегаторы, маркетплейсы и соцсети сайтом не считаются
  (`core/validators.py::BLOCKED_DOMAINS`).
- **SSL-fallback**: если цепочка TLS не проверяется (национальные УЦ — например,
  Russian Trusted Root CA у Сбербанка), страница дозагружается с `verify=False`,
  что логируется `warning`-ом. Теоретический риск MITM при активном перехватчике
  трафика — осознанный компромисс ради работоспособности.
- **Prompt injection**: текст страниц — данные из интернета и может содержать
  враждебные инструкции. Он экранируется ограничителями («данные, не
  инструкции»), а финальный ответ проходит детерминированные гварды, однако
  полной защиты от инъекций через контент страниц не существует.
- **Негативные кейсы вероятностны**: когда сайта нет, LLM изредка приписывает
  организации домен из шума выдачи. Гварды устраняют большинство таких случаев,
  но не все (см. замечание в разделе demo.py).
- **Воспроизведение без Yandex-ключа**: `SEARCH_PROVIDER=brave` + `BRAVE_API_KEY`
  (у Brave есть бесплатный тир).
